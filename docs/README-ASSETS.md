# README visuals and activity

The profile README uses the portfolio's charcoal background, white headings, gray ruler borders, compact chips, and small green availability accent. All displayed images are stored in this repository; none depend on an external badge or profile-stat rendering service.

## Static assets and animation

`assets/readme/header@3x.gif` is a typing animation rendered at **2640 × 630**, displayed at **880 × 210**. It uses a 256-color palette without downscaling its frames. The 3× source stays sharp on high-density screens while retaining the compact banner height. The name and role remain visible throughout. The README's picture element selects the equally high-resolution `header-static@3x.png` when the reader prefers reduced motion. Every visual has alternative text, and profile destinations are normal clickable links. GitHub can also show a paused/static image depending on its viewer settings.

The banner, badges, and technology chips are generated by `scripts/generate-readme-assets.mjs`, using the installed Sharp and React Icons packages. Install Pillow for Python 3, then run:

```sh
node scripts/generate-readme-assets.mjs
python3 scripts/pack-readme-animation.py
```

React Icons includes Simple Icons under its respective icon license. The artwork composed around the icons is local to this project.

## Public activity snapshot

```sh
node scripts/update-readme-activity.mjs
```

This reads the site's verified `/api/github-activity` response. It requires both sources to succeed, validates the continuous 365-day calendar and descending repository totals, and rejects incomplete data before writing. Contributions and active days cover the personal past-year calendar. Repository commits count all contributors and bots on public default branches across their complete histories. The cards label these scopes separately.

### Source lines by language

`scripts/count-public-code.py` uses the official [cloc 2.10](https://github.com/AlDanial/cloc/tree/v2.10) program, downloaded from the release tag and checked against a pinned SHA-256 checksum. It reads only owned public repositories that are not forks. Each source tree is pinned to a commit SHA, and those SHAs and per-repository line totals are retained in `activity.json`.

The counter downloads recognized source files rather than entire repositories, so large videos and datasets are not fetched. It rejects truncated trees, unsafe paths and oversized source files. Repository source is read as text and is never executed. Blank lines, comments, generated output, minified files, dependency/build directories, and data/configuration formats are excluded. Notebook JSON is parsed into code cells; outputs and markdown cells are excluded, and source lines count toward the notebook's programming language. Counts describe current repository source, including collaborative work, rather than personal typing time or skill. The six largest languages show actual line totals; the bar represents their proportions of all counted source lines.

### Daily refresh and cost

The workflow in `.github/workflows/readme-activity.yml` runs at 00:25 UTC (05:55 India time), or on manual dispatch. It uses a pinned official checkout action, standard `ubuntu-latest` runner, Python, Perl, and the repository-scoped automatic GitHub token. No AI service is called and no paid runner is configured. Standard GitHub-hosted runners in public repositories are [currently free](https://docs.github.com/en/billing/concepts/product-billing/github-actions). Private repositories and larger runners have different billing rules. No artifacts or persistent Actions caches are uploaded by this workflow.

Updates commit as `github-actions[bot]` with the message `Refresh public GitHub activity`; these are automatic data changes. A run commits only when the generated snapshot changes, and it never force-pushes. There is no push trigger, so a data commit cannot start an update loop. Failed refreshes preserve the previous snapshot. GitHub can delay scheduled runs or disable schedules on inactive repositories.

The updater changes only the marked statistics section of the README and generated files in `assets/readme`. Cards use content hashes in local filenames to bypass GitHub's image caches; query versions were dropped by GitHub's image redirects during verification. Current and preceding linked card versions are retained for cached README pages. The high-resolution banner has its own `@3x` filename. All displayed images are stored in this repository.

## Search identity correction

The old `/official/opengraphh.jpg` contained Swami Malode's name and artwork and was originally referenced by social metadata. The current metadata points to Priyanshu's own `/opengraph.png`. The legacy JPEG URL now also serves Priyanshu's preview, and the legacy placeholder logo is replaced by his local P mark. This prevents cached image URLs from continuing to return someone else's identity.

The visible design-credit link remains attributed to the original designer, with `data-nosnippet` on its text so Google can exclude it from result snippets. Google must recrawl the page and image before older result cards can update. Other search/AI providers may handle snippet controls differently.
